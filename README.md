# Replicated Inventory — Part I: Application API

A product inventory service: products with a price and a stock level, and orders that remove stock from several products at once.

The service is described twice: **OpenAPI** for clients and **protobuf** for servers. A REST layer serves every HTTP call by issuing gRPC calls.

```
            REST / JSON                           gRPC / protobuf
client ───────────────────▶  HTTP handlers  ───────────────────▶  Inventory gRPC server
        (api/openapi.yaml)   internal/httpapi   (proto/inventory/v1)  internal/grpcsvc
                             ▲ generated by                       ▲ generated by
                             │ oapi-codegen                       │ protoc
```

In Part I the gRPC server returns **dummy** values and stores nothing. In Part II it will apply operations to a state machine; in Part III it will submit them to the replicated log. The REST layer stays as it is.

## Quick start

```sh
# prerequisites: Go >= 1.26, protoc (https://protobuf.dev/installation/), make, curl
make setup        # once: pins oapi-codegen, protoc-gen-go, protoc-gen-go-grpc in go.mod
make check        # all in one: generators, build, two nodes, every status code checked

make run          # generates, builds, starts node n1 (REST :8080, gRPC :50051)
sh etc/demo.sh     # in another terminal: one curl per operation and per error

make run2         # node n2 (REST :8081) forwards everything to n1 over gRPC
sh etc/demo.sh http://localhost:8081   # names say "from n1"
```

`make build` regenerates all generated code (`gen/`) from `api/openapi.yaml` and `proto/inventory/v1/inventory.proto`, then vets and builds `bin/server`.

## The API

A product is `{sku, name, priceCents, stock, version}`. Eight REST operations are served by six RPCs.

| Method | Path | Meaning | Codes | RPC |
|---|---|---|---|---|
| `GET` | `/v1/products` | List products: `?sku=` (repeat) or `?prefix=`; `?inStock=`, `?sort=` (e.g. `-stock`), `?limit=` | 200, 400 | `ReadProducts` |
| `GET` | `/v1/products/{sku}` | Read one product; `ETag` = version | 200, 400, 404 | `ReadProducts` |
| `POST` | `/v1/products` | Create a product; `ETag` and `Location` | 201, 400, 409 | `CreateProduct` |
| `PATCH` | `/v1/products/{sku}` | Change name and/or price; optional `If-Match` | 200, 400, 404, 409, 412 | `UpdateProduct` |
| `DELETE` | `/v1/products/{sku}` | Delete one product; optional `If-Match` | 204, 400, 404, 409, 412 | `DeleteProducts` |
| `DELETE` | `/v1/products?sku=` | Delete several products, all or nothing | 204, 400, 404, 409 | `DeleteProducts` |
| `PATCH` | `/v1/products/{sku}/stock` | Add stock: `{"add": n}` (read-modify-write) | 200, 400, 404, 409 | `AddStock` |
| `POST` | `/v1/orders` | Remove stock from several products, all or nothing (read-modify-write) | 200, 400, 404, 409 | `PlaceOrder` |

- **Consistency:** reads take `?consistency=sequential|linearizable` (default sequential). All writes are linearizable. Unknown values give 400.
- **Versions:** `version` is the store revision of a product's last change (one counter for the whole store). `If-Match: "N"` writes only if the product is still at version N, otherwise 412.
- **Safe retries:** writes take optional `Client-Id` and `Request-Seq` headers. The same number again is a retry (not applied twice), a smaller one is 409.
- **Errors** are `application/problem+json` (RFC 9457). Every operation may also return 500, 501, 503 or 504.

gRPC status codes become HTTP status codes in one place, `httpStatusFromGRPC` in `internal/httpapi/handlers.go`:

| gRPC | HTTP | When |
|---|---|---|
| `NOT_FOUND` | 404 | no such product |
| `INVALID_ARGUMENT` | 400 | bad input |
| `ALREADY_EXISTS` | 409 | the SKU already exists |
| `FAILED_PRECONDITION` | 409 | not enough stock, or an old `Request-Seq` |
| `ABORTED` | 412 | `If-Match` differs from the version |
| `UNIMPLEMENTED` | 501 | RPC not written yet |
| `UNAVAILABLE` | 503 | e.g. the other node is down |
| `DEADLINE_EXCEEDED` | 504 | timeout |
| anything else | 500 | |

**Dummy data (Part I):** the server pretends to hold `apple` (stock 10, version 3), `banana` (20, v5) and `cherry` (0, v7). Any other SKU doesn't exist. Writes answer with version 8 and nothing is saved. The dummy pretends every client's last `Request-Seq` was 5.

## Inspect the gRPC side

Reflection is on, so `grpcurl` works without the `.proto` file:

```sh
grpcurl -plaintext localhost:50051 list
grpcurl -plaintext -v -d '{"singleSku":"apple"}' localhost:50051 inventory.v1.Inventory/ReadProducts   # -v shows served-by
grpcurl -plaintext -d '{"prefix":"","sort":{"field":"FIELD_STOCK","descending":true}}' localhost:50051 inventory.v1.Inventory/ReadProducts
grpcurl -plaintext -H 'client-id: alice' -H 'request-seq: 6' -d '{"sku":"apple","add":5}' localhost:50051 inventory.v1.Inventory/AddStock
```

## Editing vs. viewing the API

| Tool | Use it to | Where |
|---|---|---|
| Swagger Editor | edit `api/openapi.yaml` with live errors | `make run` → http://localhost:8080/editor, or https://editor.swagger.io |
| Swagger UI | view the API and call it with "Try it out" | `make run` → http://localhost:8080/docs |
| Docker tools (optional) | self-hosted Swagger Editor, Swagger UI, Scalar | `make tools-up` → :8090, :8091, :8092 (start the server with `make run CORS='*'`) |

No tool writes to your file: save as YAML, overwrite `api/openapi.yaml`, then `make gen-rest`.

## Layout

```
api/openapi.yaml           REST API (source of truth for clients)
api/oapi-codegen.yaml      generator config
api/spec.go, docs.html, editor.html   serve /openapi.yaml, Swagger UI at /docs, Swagger Editor at /editor
proto/inventory/v1/        gRPC service
internal/grpcsvc/          gRPC server (dummy in Part I)
internal/httpapi/          REST handlers -> gRPC client, error mapping
cmd/server/main.go         wires both servers into one process
etc/demo.sh                curl demonstration
etc/check.sh               self-checking end-to-end test (make check)
docker/                    optional self-hosted API tools
gen/                       generated code (make gen); do not edit by hand
TUTORIAL.md                the course's guide to the template
```

## Rules of thumb

- **Change the spec, then regenerate.** `var _ rest.StrictServerInterface = (*Handlers)(nil)` makes the build fail when the handlers stop matching the spec.
- **Map errors in one place:** `httpStatusFromGRPC`, consistent with the responses in `openapi.yaml`.
- **Keep handlers stateless.** All state lives behind the gRPC service, so any node can forward to another.
